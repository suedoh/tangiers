# Entry-zone checklist backtest — pre-registration (2026-11-09)

Written before any result was computed. The question: does the 4-point "would a desk
trader call this an entry zone?" checklist attached to every live alert
(`.claude/watchers/entry-check.js`) pick better trades than taking the same trade
construction at any hour? The user is a novice using it as learning data; an honest
null is a valid outcome. Prior: spec-07 rounds (155+ cells) found nothing that beat costs.

## Data
- BTCUSDT USDT-M perpetual, Binance. Candles 5m / 1h / 4h / 1d with taker-buy volume
  (repo cache `.market-data-cache/research-*.json`, extended to 2026-11-09).
- Open interest: Binance public archive `data.binance.vision` daily `metrics` files
  (`sum_open_interest`, 5-min), since the REST endpoint is capped at 30 days.

## Evaluation points
Every 1h candle close, 2021-01-01 → 2026-11-09 (2020 is warm-up for the 200-day line).
- In-sample: 2021-01-01 → 2024-12-31. Out-of-sample: 2025-01-01 → 2026-11-09.

## The checklist (identical to the live one except where noted)
At hour close t, price P = that 1h close. Scored separately for long and short.
1. **Trend** — 4h and daily EMA20/EMA50 stacks (closed bars only): long needs both
   `up` (P > EMA20 > EMA50), short needs both `down`.
2. **Location** — levels: previous UTC day high and low, 14-day VRVP VAL/POC/VAH
   (repo `buildVolumeProfile`, 5m bars, rowSize 34.7, recomputed once per UTC day —
   live recomputes continuously), daily EMA200. Levels within 0.15% of each other merge.
   Support = highest level below P, resistance = lowest above. Long ✓ if P is within
   0.3% above support; short ✓ if within 0.3% below resistance.
   **Deviation:** the live check also uses hand-picked levels (73,333, 74,909, ...);
   those cannot be replayed without hindsight, so they are excluded.
3. **Flow** — over the closing hour: CVD = 2·takerBuy − volume; OI change from the
   hour's open to its close. Long ✓ if CVD > 0 and OI > +0.15%; short ✓ if CVD < 0
   and OI > +0.15%.
4. **Reward:risk ≥ 2** — long: (resistance − P) / (P − support·0.9985); short:
   (P − support) / (resistance·1.0015 − P). No level on a side ⇒ boxes 2 and 4 fail
   and no trade can be simulated for that side.

## The simulated trade (same construction for every hour and every score)
- Entry P (at the hour close). Stop = the "wrong" point (long support·0.9985, short
  resistance·1.0015). Target = the next level (long resistance, short support).
- Resolved on 5m bars after t: first touch wins; stop and target inside the same 5m
  bar counts as the stop. Time stop 48h → exit at that 5m close.
- Costs: taker 0.06% per side (repo `TAKER`, measured from BloFin fills) + 0.02%
  slippage per side, charged in R.
- One position at a time per (side, group): a new entry is skipped while the previous
  trade of that cell is open. This keeps trades non-overlapping.

## Cells
Primary (4): long score 4, short score 4, long score ≥ 3, short score ≥ 3.
Baselines: the same side at every hour regardless of score (non-overlapping), and
score ≤ 2.
Exploratory only (not eligible to "pass"): each single box alone.

## Pass bar — all of these, per primary cell
1. Out-of-sample mean net R > 0 with a day-clustered bootstrap 95% CI above 0
   (repo `bootDayCI`, 10,000 resamples).
2. Out-of-sample mean net R above the same side's every-hour baseline, with the
   bootstrap CI of the difference above 0.
3. Same sign in-sample.
4. Survives Benjamini-Hochberg at q = 0.10 across the 4 primary cells (one-sided
   bootstrap p of mean R ≤ 0).
5. At least 150 out-of-sample trades (spec 07.1 floor).
Also reported, not gating: win rate with Wilson CI, lag-1 autocorrelation, average
risk in %, share of trades ending on the time stop.
